# spec — локальный каталог исходных постановочных документов (НЕ КОММИТИТСЯ)

**Заведён `ADR-066`** по образцу каталога `audit/` (`ADR-063`, вариант A). Содержимое в `.gitignore`
целиком; в репозиторий уходит только этот файл-опись.

## Почему не в репозиторий

Репозиторий публичный (`00 §4`). **Состав исходного ТЗ на дату заведения каталога не измерен ни
разу** — документа в контуре не было (`Q-28`). Пока он не прочитан, гарантировать, что внутри нет
сумм, имён клиентов, реквизитов и внутренних договорённостей, невозможно; а гарантировать задним
числом, после публикации в публичный репозиторий, нельзя вообще. Каталог локальный по той же
причине, по которой локален `audit/`, и это решение не пересматривается «когда посмотрим глазами».

## Что кладётся сюда владельцем

Имена файлов **не меняются**: имя есть часть провенанса.

| Что | Пример имени |
|---|---|
| Исходное ТЗ проекта | как названо у владельца (`Section7_v3_Final.*` либо иное — имя не назначается заранее) |
| Ответы интервью с сотрудниками клиента | `INTERVIEW_elkhan_ответы_YYYY-MM-DD.*` |
| Прочие постановочные документы заказчика | как названо |

## Что происходит дальше — задача `T-0-21`

1. **Проверка утверждения, а не приём на веру.** Первым делом сессия предъявляет сплошным поиском,
   действительно ли содержимого ТЗ в репозитории не было. Утверждение сделано архитектором
   2026-08-17 на одном совпадении; **если знание в документах всё же есть — вердикт правится в эту
   сторону поимённо**, а не защищается.
2. **Опись.** Перечень требований ТЗ с номерами и счёт числом. До прочтения состав разделов,
   их число и формат **называть запрещено** (третий класс гэпа, `ADR-061`).
3. **Разнесение каждого требования ровно в один из четырёх исходов:**
   - закрывается названным пунктом контракта готовности `00 §6` и названной задачей;
   - сознательно вне scope v1 (`00 §5`) — с причиной;
   - сделано иначе, чем в ТЗ, — с названием расхождения и решения, которым оно вызвано;
   - **потеряно** — не покрыто ничем; по каждому такому принимается решение «заводим строкой» либо
     «отказываемся с названной причиной».
4. **Критический разбор.** ТЗ каноном не является: проект прошёл замеры, которые часть его
   утверждений уже опровергли. Ступени усиления предъявляются с ценой в сессиях и разрезом
   «до даты поставки / после даты», а не списком пожеланий.
5. **Карта ТЗ** уезжает в публичный репозиторий отдельным документом — **без единой построчной цифры
   клиента**, как и карта аудита.

## Ограничения

- Каталог локальный: не версионируется, не переживает переклонирование, на другой машине его нет.
  Принятая цена, та же что у `audit/`.
- Потребность во второй машине или в истории правок есть условие оживления варианта B (приватный
  репозиторий-сателлит, `04 §6`).
