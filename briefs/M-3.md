## Роль

Ты — исполнитель проекта. Законы — `CLAUDE.md`, стандарты — `05_CONVENTIONS.md` Части I и II.
Модель исполнения: ты исполняешь сам в пределах мандата класса A. Не-идемпотентное и всё из списка

## Цель

Приёмка `M-3` из `04_ROADMAP.md` состоит из двух частей, и вторая не сделана (`07_STATE.md`,
подробности для модели). После этой задачи обе части предъявлены артефактами: (1) сплошной поиск
понятия «канонизац» по репозиторию перепрогнан и печать всех совпадений с решением по каждой
существует как датированный артефакт, не только как утверждение в state; (2) по тексту границы
приёмки (`00_CHARTER.md §3-БИС(c)`, guard схемы) выписан явный список проверяемых утверждений про
отпечаток схемы — это вход контрактного теста, который будет написан позже (`T-1-1`, по ADR-023(ii)
контрактный тест на границе — «отпечаток схемы плюс контракт канонического представления»), а не
код теста сам по себе.

- `mapping.json` (эталон отпечатка схемы, `02 §4`) на диске **не существует**: дискавери БД

  об отпечатке схемы пишутся про **поведение guard'а**, зафиксированное текстом конституции,
  архитектуры и `ADR-004` — НЕ про конкретные значения реальной схемы Firebird, которых ещё нет.
  Подставлять правдоподобные имена таблиц/колонок запрещено (`CLAUDE.md`, anti-improvisation) —
  при попытке это сделать: `CONTEXT GAP`.

Чего-то ещё нет → `CONTEXT GAP`, не угадывать.

## Ограничения

- К БД PawnShop эта задача не обращается вовсе — ни чтения, ни записи.
- Класс A: пишет только в `/reference` (staging-артефакты) и коммитит локально. Правка
  `00_CHARTER.md`, `01_ARCHITECTURE.md`, `02_DATA_CONTRACTS.md` (STABLE/SEMI-STABLE) — только через
  решение в журнале, в scope этой задачи не входит.
- Список обязательного контекста не копируется в новые артефакты (ADR-021): ссылка, не копия.
- Секреты и endpoint'ы контура клиента в артефакты не попадают (ADR-001).

## Шаги

1. **Перепрогнать сплошной поиск понятия «канонизац»** по всему репозиторию (не только по двум
   файлам, названным в `ADR-017` — по всему дереву, чтобы новый дрейф после `ADR-017` тоже был
   виден). Напечатать ВСЕ совпавшие строки с номерами. По каждой строке вынести явное решение:
   «согласуется с `3-БИС`» / «остаётся, дефект не найден» / «правка нужна — CONTEXT GAP» (третий
   вариант останавливает задачу, а не молча продолжается). Сохранить полный вывод и решения в
   `reference/M-3_canon_sweep_<дата>.md`. Нулевое число совпадений — тоже гэп наблюдения, если
   инструмент поиска не подтверждён обратным запросом (заведомо совпадающая строка находится).

2. **Выписать список проверяемых утверждений отпечатка схемы.** Источник — дословный текст
   `00_CHARTER.md §3-БИС(c)`, `01_ARCHITECTURE.md §3` (правила 1–4) и `ADR-004`. Каждое утверждение
   формулируется как проверяемое условие о ПОВЕДЕНИИ guard'а (не о значениях конкретной схемы),
   с указанием файла:строки-источника. Минимум, который обязан быть закрыт текстом (не додумывать
   сверх — только то, что дословно есть в источниках):
   - guard снимает отпечаток метаданных ТОЛЬКО используемых таблиц (не всей базы) перед КАЖДЫМ
     чтением;
   - отпечаток строится из RDB$-системных таблиц Firebird: колонки и типы;
   - отпечаток сверяется с эталоном, хранящимся в `mapping.json` (не в коде, не в переменной
     окружения);
   - расхождение отпечатка с эталоном даёт СТОП чтения и АЛЕРТ — чтение в этом цикле не
     выполняется вообще (не частично, не с урезанным набором колонок);
   - расхождение НИКОГДА не смягчается до предупреждения — нет режима «залогировать и продолжить»;
   - запросы к БД используют только явные списки колонок; `SELECT *` запрещён категорически;
   - обновление эталона в `mapping.json` — осознанное действие правкой конфига, а не автоматическое
     принятие нового отпечатка при расхождении.
   Если текст источников не покрывает какой-то из этих пунктов дословно — пункт не выдумывается,
   формулируется как реально написано, вплоть до пометки «текст не уточняет: <что именно», без
   заполнения правдоподобным поведением.
   Сохранить список с цитатами-источниками в
   `reference/M-3_schema_fingerprint_assertions_<дата>.md`.

3. Локальный коммит: `method: contract boundary sweep + schema fingerprint assertions (M-3)`.

## Критерии приёмки

- [ ] `reference/M-3_canon_sweep_<дата>.md` существует и содержит ВСЕ совпавшие строки поиска
      «канонизац» по репозиторию с номерами (положительным или явным нулевым счётчиком,

- [ ] `reference/M-3_schema_fingerprint_assertions_<дата>.md` существует и содержит список
      проверяемых утверждений отпечатка схемы, каждое — с цитатой и указанием файла:строки
      источника (`00_CHARTER.md`, `01_ARCHITECTURE.md`, `ADR-004`), без единого значения реальной
      схемы Firebird (таблиц/колонок/типов), которых на этот момент не существует в репозитории.
- [ ] Ни один пункт списка утверждений не опирается на `mapping.json` или другой ещё не
      существующий файл как на факт — только на текст уже принятых документов.
- [ ] Ничего не закрыто по коду возврата: у сплошного поиска — печать строк, у нулевого
      результата — обратный запрос-подтверждение.
