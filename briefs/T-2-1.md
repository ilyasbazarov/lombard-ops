## Роль

Ты — исполнитель проекта. Законы — `CLAUDE.md`, стандарты — `05_CONVENTIONS.md` Части I и II.
Модель исполнения: ты исполняешь сам в пределах мандата класса A (код `app/`, конфиги без применения,
локальный коммит). Включение Identity Platform, создание пользователей и деплой Cloud Run — класс B,
только отдельным действием после явного подтверждения Ilyas, никогда в связке с написанием кода.
Перед каждым запросом подтверждения — ОТДЕЛЬНОЕ сообщение: что именно исполняется, на каком объекте,
чем откатывается. Один скрипт на ШАГ, диагностику и класс-B действие в одном блоке не объединять.
`Done` — только по предъявленному логу, не по коду возврата.

## Цель

После задачи: сервис `app-lombard` существует как Cloud Run service в `europe-west3`, за Identity
Platform (email+пароль, без self-signup); роль пользователя читается из custom claims
(`owner`/`manager`/`assessor`); API отдаёт 401 без токена и 403 при обращении роли `assessor` к
ресурсу, зарезервированному за `owner` — оба случая предъявлены логом запроса и ответа. Экраны сверх
`/login` и минимального каркаса API — предмет `T-2-2`/`T-2-3`, вне этой задачи.

## Критерии приёмки

- `app/` существует, приложение поднимается локально и/или на Cloud Run (лог сборки/старта).
- Вход по паролю предъявлен ответом с токеном — лог запроса и ответа (шаг 8-а), не пересказ.
- Запрос к API без токена печатает 401 — лог запроса и ответа, воспроизведён и локально (шаг 2), и на
  задеплоенном сервисе (шаг 8-б).
- Запрос под ролью `assessor` к ресурсу роли `owner` печатает 403 — лог запроса и ответа, локально
  (шаг 2) и на задеплоенном сервисе (шаг 8-в).
- `gcloud run services describe app-lombard` печатает `READY` и URL в `europe-west3` — печать команды
  и вывода.
- Билд под явно названным билд-аккаунтом (`lombard-build@…`) — `builds describe` или `run services
  describe` печатает подтверждающее поле, а не предполагается по умолчанию.
- Ни один критерий не закрывается кодом возврата; пустая или непарсимая выдача при нулевом коде есть
  гэп наблюдения.
