# BRIEF · M-1 · Законы и роли: настройки инструмента, файлы ролей, замер мандата

**Класс задачи:** A
**Параллель:** нет   (единственная задача фазы M на этот момент; пары для проверки пересечения нет)

**Файлы на запись** (полный список; на нём МЕХАНИЧЕСКИ проверяется пересечение):
- `.claude/settings.json` — разрешено / спросить / запрещено на уровне инструмента
- `.claude/agents/architect.md` — бутстрап роли архитектора
- `.claude/agents/generator.md` — бутстрап роли генератора брифов
- `.claude/agents/executor.md` — бутстрап роли исполнителя
- `reference/M-1_mandate_measurement_<дата>.md` — артефакт замера мандата (`<дата>` — локальная дата дня в формате `YYYY-MM-DD`)

## Цель

Законы проекта должны подхватываться инструментом автоматически, роль должна выбираться одним
словом вместо простыни в первом сообщении, а класс мандата B должен держаться настройкой
инструмента, а не памятью сессии. После задачи запуск роли не требует ручной вставки контекста,
а попытка действия класса B **фактически** упирается в диалог подтверждения — это проверено
замером, а не предположением.

## Context-to-load (обязательно прочитать перед работой)

Файлы читаются **с диска**, не по сети (`05 §II`, «Единственный режим чтения репозитория —
с ЛОКАЛЬНОГО ДИСКА»).

- `CLAUDE.md` — законы и единственный список обязательного контекста
- `00_CHARTER.md` — красные линии `§4`, граница контракта `§3-БИС`
- `05_CONVENTIONS.md` — целиком; особенно «Модель исполнения — мандат по КЛАССУ задачи» и
  «Язык ответов владельцу»
- `07_STATE.md` — таблица мандата, стенд-ап
- `_ARCHITECT.md`, `briefs/_GENERATOR.md` — тексты, из которых собираются файлы ролей
- `reference/ARCH_METHOD-UPGRADE_2026-08-07.md` §4 (развилки 4, 5, 6) — обоснование состава класса B

## Входные артефакты

- Состав класса A и класса B — буквально в `05_CONVENTIONS` §I и в `CLAUDE.md`. **Не переписывать
  своими словами и не расширять:** расхождение между настройкой инструмента и текстом закона есть
  дефект задачи.
- Форма файла роли и файла настроек снята с оригиналов проекта-донора и разобрана в
  `reference/ARCH_METHOD-UPGRADE_2026-08-07.md` §11.4. **Чужие номера решений при переносе сняты** —
  если они где-то всплывут, это дефект, а не провенанс.

Чего-то нет → `CONTEXT GAP`, не угадывать.

### Форма файла роли (снята с оригинала, адаптирована)

Файл короткий — десять-шестнадцать строк тела плюс шапка. Шапка несёт четыре поля: `name`,
`description` (по нему роль выбирается), `model`, **`tools`**. Список инструментов и есть механизм:
он ограничивает роль физически, а не напоминанием.

| Роль | Инструменты | Почему так |
|---|---|---|
| `architect` | чтение, поиск, **запуск команд** | см. правку ниже |
| `generator` | чтение, поиск, запись | пишет бриф и session-блок, ничего не исполняет |
| `executor` | чтение, поиск, запуск команд, правка, запись | исполняет сам в пределах класса A |

**Правка против оригинала, обязательная к внесению.** У донора архитектору запуск команд НЕ выдан —
и при этом его же законы требуют от каждой сессии зафиксировать коммит командой и проверить чистоту
дерева командой. Внутри той роли эти два требования невыполнимы. У нас ритуал старта опирается на
скрипт статуса и на фиксацию коммита, поэтому **архитектору запуск команд нужен**. Ограничение
переносится с роли на список прав инструмента: читающие команды разрешены, публикация наружу
спрашивает, разрушающие запрещены. Механизм вместо памяти — тот же принцип, которым куплен хук.

## Ограничения

- К БД PawnShop — только чтение (`00 §4`). Эта задача к базе не обращается вовсе.
- Задача класса A: пишет только в репозиторий, коммитит локально. **Публикация наружу — класс B**,
  в scope не входит.
- Список обязательного контекста **не дублируется** в файлах ролей (ADR-021): на него ссылаются.
- Секреты в файлы настроек не попадают (`00 §4`, ADR-001).

## Шаги

1. **Собрать `.claude/settings.json`.** Разрешить без вопроса: чтение, поиск, `git status`,
   `git diff`, `git log`, `git rev-parse`, `git add`, `git commit`, `date`, `ls`.
   Спрашивать: `git push`. Запретить: принудительный push, жёсткий сброс, rebase, рекурсивное
   удаление.
   **Осознанная пустота, которую надо сохранить:** удаление файлов намеренно не попадает ни в один
   список — на каждое удаление инструмент спросит. Удаление есть ровно тот случай, где
   подтверждение несёт защитную функцию.
   **Знать при заполнении:** список фильтрует СТРОКУ команды, а не содержимое скрипта. Право на
   запуск произвольных скриптов не выдавать.

2. **Собрать три файла ролей** по форме выше — шапка с четырьмя полями плюс тело на 10–16 строк.
   Тело каждого обязано содержать: **ссылку** на `CLAUDE.md` за обязательным контекстом (не копию
   списка — копия запрещена, три копии уже разошлись однажды), запрет выдумывать с меткой
   `CONTEXT GAP`, класс мандата роли, требование session-блока в конце и правило языка ответов
   дословно («сообщение без внутренних идентификаторов; ответ открывается коротким блоком обычными
   словами и кончается тем, что делать; нет блока — ответ не принят»).
   Архитектор: не пишет прод-код, не исполняет действия класса B, выход — решения и drop-in-патчи,
   `proposed` без апрува не применяется.
   Генератор: задачу не выполняет; **обязан процитировать дословно текущий фокус и строку статуса
   задачи из состояния ПЕРВЫМ, до сборки брифа** — это даёт Ilyas поймать рассинхрон до, а не после;
   заполняет машиночитаемую шапку.
   Исполнитель: ровно один бриф, не правит STABLE-документы, **не назначает правил**; перед запросом
   подтверждения класса B — отдельное сообщение «что, на каком объекте, чем откатывается».

3. **Замер, что законы подхватываются.** Запустить свежую сессию ролью архитектора **без вставки
   контекста в первое сообщение** и попросить её напечатать перечень фактически прочитанных
   документов. Перечень сохранить в артефакт замера.

4. **Замер мандата.** В той же сессии инициировать действие класса B (попытку публикации наружу) и
   зафиксировать, что инструмент **фактически** показал диалог подтверждения. Лог диалога — в
   артефакт замера. Нулевой код возврата или отсутствие сообщения об ошибке фактом не является.

5. Локальный коммит: `method: laws and roles (M-1)`.

## Приёмка (критерии done)

- [ ] `git ls-files` печатает **положительным счётчиком** четыре новых пути: файл настроек и три
      файла ролей. Пустая или отсутствующая выдача фактом не является.
- [ ] Артефакт замера содержит перечень документов, прочитанных сессией, запущенной одним
      словом-ролью, и в перечне **есть `05_CONVENTIONS.md`**. Это прямая проверка отказа, который
      уже случался: сессия, стартовавшая по неполному списку, нарушает правила агента в первом
      же ответе.
- [ ] Артефакт замера содержит **лог диалога подтверждения** на действие класса B. Формулировка
      «настроено правильно» приёмкой не является — нужен лог.
- [ ] Ни один файл роли не содержит копии списка обязательного контекста — проверено сплошным
      поиском с печатью совпавших строк; ноль подтверждён обратным запросом.
- [ ] Секретов в новых файлах нет — сплошной поиск по категориям запрета `ADR-001` с печатью
      совпавших строк.

## Вне scope этой задачи

- `CLAUDE.md` — **уже в репозитории** (коммит `ad78bef`), эта задача его не правит, а читает.
- `tools/` и хук — задача `M-4`.
- Буфер, проход сборки, скрипт проверки пересечения — **отложенная часть** `ADR-025`, задача `M-6`.
  Закон «одно рабочее дерево на сессию» из того же решения **принят** и приходит патчем П-2-БИС;
  тело файла роли исполнителя обязано его нести строкой, а тело роли архитектора — нет
  (архитектор в репозиторий не пишет).
- Публикация наружу.
