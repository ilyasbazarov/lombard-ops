## Роль

Ты — исполнитель проекта. Законы — `CLAUDE.md`, стандарты — `05_CONVENTIONS.md` Части I и II.
Модель исполнения — Opus (отступление названо в шапке, причина указана). Мандат — класс A: чтение,

сервер клиента, ни мессенджер не затрагиваются.
`Done` — только по предъявленному логу, не по коду возврата.

## Цель

После задачи в публичном репозитории лежит документ-оглавление первичного аудита клиента (`audit/`):
какие блоки в нём есть, что в каждом, их статус, где физически лежит источник, и какие утверждения
аудита уже употреблены в наших документах — с датой и меткой достоверности. Ни одной построчной
цифры клиента (сумма, имя, VIN, номер договора) документ не несёт. Вторая половина `Q-25` («что из
аудита переносится в контур») закрывается этим документом.

## Шаги

1. **Листинг каталога и сверка с известными фактами.** Запустить:
   ```bash
   ls -la audit/
   file audit/*.docx
   ```
   Ожидаемый вывод: список файлов совпадает по составу с описанным в паспорте входов (8 `APP_*`, 5
   `AUDIT_STATE*`, `Diagnostic_Report_FINAL.docx`, `README.md`); `file` подтверждает, что оба
   `.docx` — Microsoft Word. Расхождение состава с паспортом (новый файл, пропавший файл) → назвать
   явно в артефакте, это не блокирует задачу, но искажает карту, если умолчать.

2. **Прочитать markdown-артефакты каталога как есть** (`Read` по каждому файлу `APP_*.md` и
   `AUDIT_STATE*.md`, кроме `APP_A_portfolio.md.docx`, который markdown не является несмотря на имя).
   Для каждого зафиксировать во временных заметках: домен/блок, статус (завершён/черновик/иное — по
   тексту файла, не по догадке), одна-две строки о содержимом БЕЗ построчных цифр.

3. **Прочитать оба `.docx` другим способом, чем markdown** (это прямое требование приёмки). Способ,
   не требующий внешних библиотек (`05 §II`, минимум зависимостей):
   ```bash
   mkdir -p /tmp/T-0-20_docx && cd /tmp/T-0-20_docx
   for f in Diagnostic_Report_FINAL APP_A_portfolio.md; do
     rm -rf "$f" && mkdir "$f"
     unzip -q -o "$OLDPWD/audit/$f.docx" -d "$f"
     python3 -c "
import re
with open('$f/word/document.xml', encoding='utf-8') as fh:
    xml = fh.read()
text = re.sub(r'<[^>]+>', ' ', xml)
text = re.sub(r'\s+', ' ', text).strip()
print(text[:4000])
print('... (обрезано, длина полного текста:', len(text), 'символов)')
"
   done
   ```
   Ожидаемый вывод: читаемый (без XML-тегов) текст обоих документов, достаточный для определения
   блока/статуса/содержимого без цитирования построчных цифр. Если `unzip` или `python3` недоступны
   на машине исполнения — `CONTEXT GAP`, не подбирать другой недоступный инструмент молча.

4. **Сплошной поиск утверждений аудита, уже употреблённых в наших документах.** По каждому маркеру
   блока (имена файлов без расширения, `RF-1`…`RF-5`, характерные термины блока, найденные в шагах
   2–3) прогнать поиск по всему репозиторию (кроме `audit/`, `reference/` с уже датированными
   находками и самого нового документа):
   ```bash
   grep -rn "APP_A_portfolio\|AUDIT_STATE\|Diagnostic_Report\|RF-1\|RF-4\|RF-5" \
     --include="*.md" . | grep -v "^./audit/\|^./reference/T-0-20_audit_map"
   ```
