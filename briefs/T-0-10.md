Дамп структуры БД PawnShop (T-0-2) перестаёт быть файлом на машине Ilyas: он лежит
в приватном версионированном хранилище с описанным происхождением, а из него

Ни одной угаданной строки: всё либо из файла, либо помечено CONTEXT GAP.

## Ограничения

- **Публичный репо (ADR-001, ADR-009):** `meta_out.txt` и любой полный инвентарь
  схемы вендора в `lombard-ops` НЕ коммитятся. В публичный репо уходит только
  производный маппинг used-полей (`02 §3`, `/connector/mapping.json`).
- **Схему не угадывать (05 §I):** любая строка маппинга — из `meta_out.txt`.
  Колонки, которых в файле нет, — CONTEXT GAP, не заглушка с догадкой.
- **Семантика ≠ структура (ADR-011, ADR-013):** файл даёт имена, типы и описания
  вендора. Он НЕ даёт подтверждения смысла. Каждая строка маппинга получает
  колонку «оракул» с одним из значений: `metadata_descr` (описание вендора),
  `confirmed_live` (подтверждён SELECT'ом в T-0-3), `hypothesis` (только имя/тип).
  Строка со значением `hypothesis` не используется в формулах 03 §4.
- **ПДн:** файл содержит только метаданные, но при цитировании описаний в
  артефактах — проверить отсутствие примеров с ПДн.
- **Модель исполнения (05 §I):** Sonnet пишет скрипт разбора + ожидаемый вывод;
  запускает Ilyas на своём Маке и возвращает логи; done только после
  подтверждённого человеком лога.

## Шаги

1. **Уложить дамп в приватное хранилище.** Ilyas коммитит в
   `lombard-ops-vendor-schema`:
   - `schema-snapshots/2026-07-14_meta_out.txt` — файл как есть, без правок;
   - `schema-snapshots/README.md` — происхождение: задача T-0-2, дата 2026-07-14,
     источник `D:\PawnShop_DOL\DB\DOL.FDB`, метод (isql + `meta_dump.sql`), размер,
     108 таблиц / 1018 колонок, версия билда PawnShop — `⏳ T-0-12`.
   Причина именно git, а не GCS: снимки схемы нужно **диффать** между версиями
   PawnShop (вендор не уведомляет об обновлениях), git это даёт из коробки.

2. **Написать парсер `scripts/parse_meta_dump.py`** (Python, стандартная библиотека,
   без внешних зависимостей — 05 §II «минимум зависимостей»). Вход `meta_out.txt`,
   выходы:
   - `schema_index.md` — инвентарь: таблица, число колонок, русское описание таблицы;
     отсортировано. **Идёт в приватный репо**, служит поисковиком по схеме для
     будущих сессий вместо перечитывания 1.7 МБ.
   - `fingerprint_used.json` — fingerprint used-таблиц **с колонкой `descr`**, тот
     же формат, что в `mapping.json`, но обогащённый описаниями.
   Ожидаемый вывод скрипта: две строки-счётчика — «таблиц разобрано: 108»,
   «колонок разобрано: 1018». Не совпало → парсер врёт, не «подгонять», а починить.

3. **Обогатить `/connector/mapping.json` → v0.2.** Механически, из `descr`:
   а. Во все существующие 17 полей добавить `descr` вендора и колонку `oracle`
      (значения по правилу из «Ограничений»: `confirmed_live` для полей, у которых
      в v0.1 стоит `confirmed_live: true`; `metadata_descr` — где есть описание;
      `hypothesis` — где только имя и тип).
   б. **Добавить пропущенные поля.** Обязательный список, все из
      `CONTRACTS_TERMS` и `CONTRACTS`, все нужны для ADR-006:
      `MIN_PERC_DAYS`, `IS_PERC_STOP_W_PEN`, `IS_PENAL_FROM_RET_SUM`,
      `EXCEED_DAYS`, `EXCEED_MONTHS`, `IS_PRIVILEGE_IN_EXCEED_DAYS`,
      `START_MOMENT`, `ACC_PAY_SCHEME`, `TARIFF_NAME`, `ID_TARIF`,
      `STORAGE_TYPE`, `STORAGE_MIN_DAYS`, `IS_STORAGE_STOP_W_PEN`,
      `INSURE_MIN_DAYS`, `IS_INSURE_STOP_W_PEN`,
      `IS_NOT_CALC_FIRST_DAY`, `SUM_ROUND_PRECISION`,
      `USE_EXCHANGE`, `USE_EXCHANGE_IF_INCREASE`, `EXCHANGE_RATE`,
      `SUBJECT_PRICE`, `DEPOSIT_TYPE`, `ID_DEPOSIT_PLACE`, `FILIAL_ID`,
      `IS_ARCHIVE`, `MODIFY_DATE`, `CONTRACT_NUM`.
      Каждое — с типом из файла, русским описанием и `oracle: metadata_descr` либо
      `hypothesis`. **Расшифровку значений/формул не придумывать** — это T-0-3b.
   в. Отдельной секцией `open_questions` перенести в файл: расшифровка
      `STORAGE_TYPE`, база и период начисления хранения, надёжность `MODIFY_DATE`
      как watermark, валюта договоров (`USE_EXCHANGE`/`EXCHANGE_RATE`).
   г. `version` → `0.2`, `status` → описание фактического состояния.

4. **Заполнить `02 §3`** из `mapping.json` v0.2, с новой колонкой «Оракул»
   (правка SEMI-STABLE-документа через session-блок с пометкой — 05 §Дисциплина
   документации). Формат таблицы — как в `02 §3`, плюс колонка «Оракул».

5. **Свести список расхождений** между тем, что нужно формуле `03 §4`, и тем, что
   подтверждено оракулом уровня `confirmed_live`. Этот список — вход для T-0-3b.
