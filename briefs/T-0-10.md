**Формат файла (проверено архитектором, не угадывать заново):** 1 771 662 байт, UTF-8, две секции
с фиксированной шириной колонок:

   `=====`).
2. Детали колонок: `TABLE_NAME` / `POS` / `COLUMN_NAME` / `FTYPE` / `FSUBTYPE` / `FLEN` / `FSCALE`

   совпадает с `RDB$FIELD_TYPE`: например `8`=INTEGER, `12`=DATE, `37`=VARCHAR — то же поле, что
   снимает `schema_guard.fingerprint_table` через `RDB$FIELD_TYPE`); подтверждается только тем, что
   значения одноимённые, окончательной сверки с живым `RDB$FIELDS` в этой задаче нет (внешнего
   подключения к базе не требуется и не делается).

**КРИТИЧЕСКАЯ ДЕТАЛЬ ПАРСИНГА, обязательна к соблюдению.** В секции 2 сверх 1018 строк данных есть
ещё 109 строк, которые НЕ начинаются валидным именем таблицы (пример устройства — построчные
перечисления внутри `COLUMN_DESCR`, вида `- 1 - мужской; - 0 - женский`, перенесённые дампом на
следующую строку из-за длины). Это ПРОДОЛЖЕНИЯ предыдущей строки `COLUMN_DESCR`, а не новые строки
данных. Парсер обязан их СКЛЕИВАТЬ с предыдущей распознанной строкой (конкатенация в поле
`COLUMN_DESCR` через пробел или перевод строки), а не отбрасывать и не считать самостоятельной
строкой — иначе счётчик «строк разобрано» разойдётся с 1018, и колонки одной таблицы съедут по
позиции у следующей. Признак начала новой строки данных: первый непробельный токен строки — имя
таблицы, само встречающееся как `TABLE_NAME` где-то в файле (проверяется, например, множеством
имён из секции 1, либо регулярным выражением на формат первой колонки — это решает исполнитель по
факту структуры, лога ради строки «нашёл N строк-продолжений, все склеены» достаточно).

## Шаги

1. **Написать парсер `meta_out.txt` → структуры Python** (скрипт можно временный, не обязателен к
   коммиту в `connector/`, но лог его прогона идёт в артефакт). Разобрать секцию 2 в список записей
   `{table, pos, column, ftype, fsubtype, flen, fscale, notnull, descr}`, склеивая строки-продолжения
   по правилу выше. Напечатать: число распознанных строк данных, число склеенных строк-продолжений,
   и что сумма (1018 + 109) совпала с полным числом непустых строк секции 2 — если не совпало,
   парсер неверен, чинить, не подгонять.

2. **Собрать `schema_fingerprint` по девяти used-таблицам.** Для каждой таблицы из
   `access_point.ALLOWED_TABLES` — список записей `[COLUMN_NAME, FTYPE, FLEN, FSCALE]`,
   отсортированный по `POS` (по возрастанию — тот же порядок, что даёт `ORDER BY
   f.RDB$FIELD_POSITION` в `schema_guard._FINGERPRINT_SQL`), формат ЭЛЕМЕНТА строки — ровно тот,
   что возвращает `schema_guard.fingerprint_table` (четыре поля на колонку, `COLUMN_NAME` как
   строка без хвостовых пробелов). Положить результат в `connector/mapping.json` под ключом
   `schema_fingerprint`, по таблице на подключ.

3. **Собрать маппинг used-полей** — секция `02 §3`-совместимая (по каждой используемой колонке:
   таблица.колонка Firebird, тип, русское описание из `COLUMN_DESCR`). Ограничиться колонками,
   реально фигурирующими в текущем маппинге `02 §3` (contract_id, contract_num, VIN-поле,
   issue_date, due_date, loan_amount, rate, пени-правила, хранение, страховка, renewals-механизм —
   список таблиц/колонок уже назван в `02_DATA_CONTRACTS.md §3` дословно), плюс девятью used-таблицами
   целиком не подменять — маппинг used-**полей**, не полный дамп девяти таблиц: остальные колонки
   девяти таблиц входят только в `schema_fingerprint` (guard видит всю таблицу), не в человеческий
   маппинг. Положить под ключ `field_mapping`, значение `oracle` для каждой строки НЕ проставлять
   (не измерено этой задачей) — оставить явное `"oracle": "not_assessed"` либо аналогичную явную
   метку, не путать с `T-0-3b`.

4. **Дописать метаданные файла:** `version: "1.0"`, `source: "meta_out.txt (2026-08-18, вне
   репозитория)"`, `generated_by` — имя парсера/шага, `table_count: 9`, `column_count` — фактическое
   число колонок в `schema_fingerprint` суммарно.

5. **Написать тест guard'а на mock-соединении** (файл временный либо `reference/`-скрипт, лог в
   артефакт — не обязателен постоянным файлом в `connector/`, если задача не заводит отдельный
   `test_mapping_fingerprint.py`; решение о постоянном тесте — на усмотрение исполнителя, лог важнее
   формы):
   - **Положительный прогон:** `schema_guard.guard_check` с эталоном, ВЗЯТЫМ из
     `connector/mapping.json["schema_fingerprint"]`, и mock-измерением, ВОЗВРАЩАЮЩИМ ТЕ ЖЕ САМЫЕ
     значения — проходит молча (не бросает `SchemaGuardMismatch`), лог печатает «отпечаток всех 9
     таблиц совпал».
   - **Отрицательный прогон:** тот же эталон, mock-измерение с ОДНИМ подменённым типом (`FIELD_TYPE`)
     у одной колонки одной used-таблицы — `guard_check` бросает `SchemaGuardMismatch`, лог печатает
     `GUARD MISMATCH <table>: эталон=... ИЗМЕРЕНО=...` с именем именно той таблицы.
   - Оба лога — в `reference/T-0-10_mapping_fingerprint_2026-08-18.md`, дословно, не пересказом.

## Критерии приёмки
- `connector/mapping.json` существует, валиден как JSON, несёт `schema_fingerprint` по каждой из
  девяти used-таблиц (`CONTRACTS`, `CONTRACTS_TERMS`, `SUBJECTS`, `CUSTOM_FIELDS_VALUES`,
  `DIR_CUSTOM_FIELDS`, `TABLES_TABLE`, `CONTRACT_STATES`, `DEPOSIT_TYPES`, `OPERATIONS`) —
  печать: список ключей `schema_fingerprint` совпадает с `ALLOWED_TABLES` построчно, обе стороны.
- Отрицательный прогон: подмена одного `FIELD_TYPE` в эталоне даёт `SchemaGuardMismatch` — лог
  отказа с именем таблицы предъявлен дословно в артефакте.
- Положительный прогон: нетронутый эталон проходит `guard_check` молча (без исключения) — лог
  «отпечаток всех 9 таблиц совпал» предъявлен.
- Лог парсера: «строк данных секции 2 разобрано: 1018», «строк-продолжений склеено: 109» — оба
  числа предъявлены, их сумма сходится со счётом непустых строк секции.
- Ни одного обращения к БД PawnShop за всю задачу — предъявлено отсутствием любого импорта `fdb`
  вне уже существующего кода `access_point.py`/`schema_guard.py`, которые в этой задаче не
  исполняются против реального соединения.
- `meta_out.txt` не встречается в диффе коммита ни файлом, ни вставкой длиннее нескольких строк
  примера — предъявлено `git show --stat` и построчным просмотром диффа артефакта.
