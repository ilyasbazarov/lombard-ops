- DDL-правка применяется к реальному датасету `lombard_ops` — класс B, только по карточке; ALTER

  строк) печатается ДО изменения отдельной командой, не в одном блоке с самим изменением.
- Реестр, карточка, форма осмотра (`T-2-2`, `T-2-3`, `T-2-5`) этой задачей не пишутся — только

## Критерии приёмки
- `bq query` печатает счёт строк `vehicle_catalog`, распределение по `liquidity_class`, счёт строк
  `price_source = synthetic` — числа из шага 11, не пересказ.
- Марки, классы и `LTV макс` сходятся с дефолтами `03 §3` построчно — обе стороны напечатаны (шаг 5).
- Экран `/catalog` печатает те же строки, что и `bq query`, и несёт пометку о синтетическом
  справочнике, пока такие строки есть — снимок экрана (шаг 13).
- Ни один шаг задачи не читает `audit/` — сплошной поиск с печатью совпадений, пусто, обратный
  контроль исправности предъявлен (шаг 14).
- Если `data_inbox/vehicle_catalog.csv` предоставлен владельцем до конца сессии — счёт строк
  `price_source = client` больше нуля, `buyout_price` этих строк не печатается ни в чат, ни в
  `reference/`, ни в коммит; если не предоставлен — счёт равен нулю, и это названо явно, а не
  тихо (паспорт входов, строка 5).
- `data_inbox/vehicle_catalog.csv` и `data_inbox/vehicle_catalog_seed.json` отсутствуют в патче —
  `git show --stat <коммит>` не содержит этих путей (проверка «отсутствием цен в патче»).
- `gcloud run services describe app-lombard` печатает актуальную ревизию под явно названным
  билд-аккаунтом `lombard-build@…`.
- Ни один критерий не закрывается кодом возврата; пустая или непарсимая выдача при нулевом коде
  есть гэп наблюдения.
