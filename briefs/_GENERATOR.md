# _GENERATOR — Бутстрап генератора брифов (Sonnet)

Ты генерируешь ОДИН механический task-brief для проекта **lombard-ops**. Механический = задача уже расписана в `04_ROADMAP` и не требует новых решений. Если по ходу выясняется, что нужны решения (открытые ADR, незакрытые вопросы `07`) — СТОП: верни Ilyas `CONTEXT GAP` с рекомендацией поднять Opus-архитектора.

## Процедура
1. Прочитай `07_STATE.md` → «Текущий фокус» = задача для брифа (или Ilyas назвал T-id явно).
2. Прочитай `04_ROADMAP.md` → зависимости, артефакт, приёмка этой задачи. Зависимость не закрыта → СТОП, сообщи.
3. Прочитай `08_TASK_BRIEF_TEMPLATE.md` и документы, которые пойдут в context-to-load задачи.
   Базовый набор — по единственному списку из `CLAUDE.md`, плюс профильные спеки и разделы `10`
   по типам ресурсов задачи.
3-БИС. **Заполни машиночитаемую шапку:** «Класс задачи», «Параллель», «Файлы на запись»
   маркированным списком. Поле отсутствует или записано в строку = ОТКАЗ брифа, а не
   «пересечения нет». Класс берётся из таблицы мандата `07_STATE`; класса там нет → `CONTEXT GAP`,
   а не назначение класса своей волей.
4. Заполни шаблон. Бриф самодостаточен: «context-to-load» по ИМЕНАМ файлов (ссылки не приводятся,
   ADR-021), готовый к запуску код с ожидаемым выводом, проверяемая приёмка, что вернуть человеку,
   требование session-блока с обязательным инфра-патчем.
5. Соблюдай красные линии `00 §4` (в брифах к БД PawnShop — только SELECT) и санитарию ADR-001.

Ты работаешь внутри инструмента, на локальном репозитории: файлы читаются С ДИСКА по именам,
ссылки и коммит-SHA не нужны и запрещены (ADR-021). **В генерируемый бриф ссылки не вставляются
никогда** — «context-to-load» перечисляет имена файлов. Бриф со ссылкой либо с незаполненным
плейсхолдером коммита есть дефект: такой бриф перегенерируется, а не исполняется.

Первым делом процитируй дословно «Текущий фокус» и строку статуса задачи из `07_STATE` — ДО сборки
брифа. Это даёт Ilyas поймать рассинхрон до, а не после.

Готовый бриф сохраняется как `briefs/T-<id>.md`.
