**Кем исполняется (ADR-030):** исполнитель · модель sonnet (поле `model` в `.claude/agents/executor.md`)

**Параллель:** нет

**Файлы на запись** (полный список; на нём МЕХАНИЧЕСКИ проверяется пересечение):

## Роль
Ты — исполнитель проекта. Законы — `CLAUDE.md`, стандарты — `05_CONVENTIONS.md` Части I и II.
Модель исполнения: ты исполняешь сам в пределах мандата класса A. Не-идемпотентное и всё из
списка класса B — только отдельным действием после явного подтверждения Ilyas, никогда в связке
с диагностикой. `Done` — только по предъявленному логу, не по коду возврата.

## Цель

Правило «непересечение наборов „Файлы на запись“ — необходимое условие параллели» перестаёт быть
устным. После задачи существует скрипт, который на паре реальных брифов репозитория механически
печатает оба набора целиком с указанием источника (какой файл из какого брифа) и все пересечения
между ними; на брифе без поля «Файлы на запись» печатает явный ОТКАЗ, а не молчаливое «пересечений
нет»; и отдельной, третьей категорией строк отмечает совпадения по общему сериализуемому ресурсу
(`07_STATE.md`, `07_GAPS.md`, `06_DECISIONS_LOG.md`, `06_INDEX.md`, `07_ARCHIVE.md`), который по
решению `ADR-028` пересечением не считается, но при параллельном запуске требует буфера.

## Входы

- Реальные брифы репозитория как вход замера — каталог `briefs/`: на момент постановки задачи в
  нём лежат `M-1.md`, `M-3.md`, `M-4.md` (несут поле «Файлы на запись» в актуальной форме
  шаблона — годятся для позитивного случая) и `T-0-2.md`, `T-0-3.md`, `T-0-5.md`, `T-0-10.md`

  на момент исполнения проверить `ls briefs/` заново, не полагаться на этот список как на
  зафиксированный факт.
- Пять имён общего сериализуемого ресурса — дословно из `08_TASK_BRIEF_TEMPLATE.md`:
  `07_STATE.md`, `07_GAPS.md`, `06_DECISIONS_LOG.md`, `06_INDEX.md`, `07_ARCHIVE.md`.

## Ограничения

- К БД PawnShop эта задача не обращается.
- Класс A: пишет в репозиторий, коммитит локально. Публикация наружу — класс B, вне scope.
- Скрипт печатает вердикт **положительным счётчиком** (число найденных пересечений/отказов), не
  голым листингом — пусто и один служебный файл выглядят одинаково.
- Извлечение списка «Файлы на запись» из брифа — точным разбором заголовка `**Файлы на запись**`
  и маркированных строк под ним, а не эвристикой по словам «файл» где-то в тексте: иначе прозаические
  упоминания путей дадут ложные пересечения.
- Пять имён общего ресурса — жёстко зашитый список из `08_TASK_BRIEF_TEMPLATE.md`, не «всё, что
  похоже на состояние»: расширять или сокращать список самовольно запрещено (anti-improvisation).

## Шаги

1. **Написать `tools/intersect_check.sh`.** Принимает пути к двум брифам аргументами. Извлекает из
   каждого блок под заголовком `**Файлы на запись**` до следующего заголовка того же уровня или
   конца секции; из маркированных строк берёт первый токен в обратных кавычках как путь. Печатает
   оба набора целиком, каждая строка — с указанием источника (имя брифа). Если у брифа заголовка
   «Файлы на запись» нет или список под ним пуст — скрипт печатает строку явного ОТКАЗА для этого
   брифа и завершается ненулевым кодом; не печатает «пересечений нет».

2. **Логика пересечения.** Когда у обоих брифов список есть: сравнить множества путей (с учётом
   правила «каталог со слэшем поглощает вложенные файлы» из `08_TASK_BRIEF_TEMPLATE.md`).
   Пересечения, совпавшие с одним из пяти имён общего сериализуемого ресурса, печатать отдельной
   категорией строк с меткой «общий сериализуемый ресурс (ADR-028)» — не как обычное пересечение.
   Остальные совпадения — как обычное пересечение, положительным счётчиком.

3. **Замер на реальных брифах, не на синтетике.** Прогнать скрипт минимум на трёх реальных парах
   из каталога `briefs/`:
   - пара из двух брифов актуального формата с непересекающимися наборами — лог с обоими
     наборами и нулём пересечений;
   - пара, где хотя бы один брифов — старого формата без поля «Файлы на запись» — лог с явным
     ОТКАЗом, не «пересечений нет»;
   - при наличии в текущих брифах совпадения по имени из пятёрки общего ресурса — лог с этой
     строкой, помеченной отдельно; если такого совпадения в реальных брифах не находится —
     напечатать это словами как факт замера, не выдумывать пару.
   Все три лога — в артефакт `reference/M-6a_intersect_measurement_<дата>.md` целиком, не пересказом.

4. Локальный коммит: `method: intersect check script (M-6a)`.

## Критерии приёмки

- [ ] На паре брифов с полем «Файлы на запись» скрипт печатает ОБА набора целиком с указанием
      источника (какой путь из какого брифа) и все пересечения — предъявлен лог.
- [ ] На брифе без поля скрипт печатает ОТКАЗ (не «пересечений нет») — предъявлен лог.
- [ ] Совпадение по одному из пяти имён общего сериализуемого ресурса печатается отдельной строкой
      с меткой, отличной от обычного пересечения — предъявлен лог, либо предъявлен факт словами,
      что такого совпадения в реальных брифах на момент замера не найдено.
- [ ] Замер прогнан на РЕАЛЬНЫХ брифах репозитория (каталог `briefs/`), не на синтетических
      файлах, специально сочинённых под тест.
- [ ] Ни один критерий не закрыт по коду возврата: у каждого предъявлен лог с текстом вывода.
