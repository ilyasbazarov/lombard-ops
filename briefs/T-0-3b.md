- **Три семейства начислений в `CONTRACTS_TERMS`** — проценты, хранение, страховка; `STORAGE_VAL`
  типом идентичен процентной ставке (`ADR-010 v3`). Полные имена и типы остальных полей НЕ известны
  и не угадываются — их снимает шаг 2.
- **Число от владельца: шесть договоров портфеля несут начисление за хранение** по тарифу прошлого
  года (`ADR-010 v3`). Это независимый контрольный счёт, а не наш замер: расхождение с замером есть

- **Ловушка BOM, подтверждена замером дважды:** `Set-Content -Encoding UTF8` в Windows PowerShell
  пишет BOM, и `isql` падает на первой строке с `Token unknown`. Файлы запросов писать через

- **Канонический вызов клиента (`ADR-036`):** `-i <файл запроса> -o <файл результата>` и строка

  open` ещё до всякой проверки, и это трижды читалось как провал шага, который не исполнялся.

## Ограничения

- **К БД PawnShop — только чтение** (`00 §4`). Ни одной операции записи, ни `GRANT`, ни `UPDATE`,
  ни `INSERT`, ни правки метаданных — здесь нет исключения, которое было у `T-0-5`.
- **Каждый файл запроса открывается транзакцией только на чтение и доказывает это положительным
  фактом.** Первые строки любого запроса к базе клиента:
  `COMMIT; SET TRANSACTION READ ONLY;` и `SELECT MON$READ_ONLY ... FROM MON$TRANSACTIONS WHERE
  MON$TRANSACTION_ID = CURRENT_TRANSACTION;`. Признак режима печатается в лог ДО полезных запросов.
  Это не ритуал: замер `T-0-17` показал, что режим отбивает изменение на уровне задеваемой записи
  (`ADR-037`), то есть он реально работает как второй рубеж против нашей же ошибки.
- **Файл запроса печатается целиком ДО запуска** — действующий основной контроль, пока не заведена
  единственная точка доступа с белым списком операторов.
- **`SELECT *` запрещён** — везде явные списки колонок.
- **Санитария, разрез назван решением `ADR-039` и цитируется дословно.**
  МОЖНО в публичный репозиторий: имена таблиц и колонок, которые мы РЕАЛЬНО используем, их типы и
  смысл — это и есть маппинг `02 §3`, прямо разрешённый `ADR-009`.
  НЕЛЬЗЯ: полный или частичный инвентарь схемы, перечни неиспользуемых объектов, значения строк с
  данными клиентов, **номера договоров, имена людей**.
  Правило разреза: **в репозиторий попадает то, что мы используем, а не то, что мы увидели.**
- **Договоры в артефактах нумеруются порядково** («договор 1»…«договор 6»). Соответствие
  порядкового номера реальному остаётся у Ilyas вне репозиториев вместе со снимками экрана.
- **Недостоверный вывод:** побитый при копировании из RDP лог фактом не является. Не примирять
  противоречия догадкой — запросить чистый повторный лог.
- **Пустая выдача при нулевом коде возврата — гэп наблюдения**, а не «данных нет».

## Шаги

### Шаг 1 — подключение и два положительных контроля (класс B, только чтение)

Один скрипт на весь шаг. Проверяет три вещи разом: клиент на месте, соединение под `LOMBARD_RO`
живо, режим только на чтение включается.

- **Карточка подтверждения (отдельным сообщением ДО запуска).**
  - Что исполняется: три запроса `SELECT` — версия движка, признак режима транзакции, счётчик строк
    одной разрешённой таблицы. Ни одной операции изменения.
  - На каком объекте: база PawnShop, `localhost/3057:D:\PawnShop_DOL\DB\DOL.FDB`, учётная запись
    `LOMBARD_RO`.
  - Чем откатывается: откат не нужен и не имеет предмета — шаг только читает.

```powershell
# ШАГ 1 — подключение и положительные контроли. Только чтение.
# Запускать на сервере ERP по RDP. Одна команда на весь шаг (05 §I).
$fbRoot = 'C:\Program Files (x86)\Firebird-2.5-PawnShop\'
$isql   = Join-Path $fbRoot 'bin\isql.exe'
if (-not (Test-Path $isql)) { Write-Host "CONTEXT GAP: не найден isql по пути $isql"; return }

$work = 'C:\Temp\lombard'
New-Item -ItemType Directory -Force -Path $work | Out-Null
$q   = Join-Path $work 't03b_step1.sql'
$out = Join-Path $work 't03b_step1_out.txt'
Remove-Item -Path $out -Force -ErrorAction SilentlyContinue   # чистый файл результата

$sql = @'
SET LIST ON;
COMMIT;
SET TRANSACTION READ ONLY;
SELECT MON$TRANSACTION_ID AS TX_ID, MON$READ_ONLY AS RO_FLAG
  FROM MON$TRANSACTIONS WHERE MON$TRANSACTION_ID = CURRENT_TRANSACTION;
SELECT RDB$GET_CONTEXT('SYSTEM','ENGINE_VERSION') AS ENGINE_VERSION FROM RDB$DATABASE;
SELECT COUNT(*) AS CNT_CONTRACTS FROM CONTRACTS;
COMMIT;
'@
[System.IO.File]::WriteAllText($q, $sql, (New-Object System.Text.UTF8Encoding($false)))

# Фикстура: первые байты файла ДО запуска. Ожидается "83 69 84", НЕ "239 187 191".
Write-Host "первые байты файла запроса:" (([System.IO.File]::ReadAllBytes($q))[0..7] -join ' ')
Write-Host "--- файл запроса целиком, до запуска ---"
Get-Content -Path $q -Encoding UTF8
Write-Host "--- конец файла запроса ---"

$ro = Read-Host 'Учётная запись LOMBARD_RO — введите её пароль'
& $isql -user LOMBARD_RO -pas $ro -e -m -i $q -o $out "localhost/3057:D:\PawnShop_DOL\DB\DOL.FDB"
Write-Host "код возврата isql: $LASTEXITCODE"
Get-Content -Path $out -Encoding UTF8
```

**Ожидается:** `RO_FLAG` напечатан (значение записывается как есть), версия движка содержит `2.5`,
`CNT_CONTRACTS` — число.
**Известный риск и что делать, не подбирая наугад:** отказ `Function unknown` на
`RDB$GET_CONTEXT` → версию движка снять отдельной командой `isql -z -user LOMBARD_RO -pas <пароль>
"localhost/3057:D:\PawnShop_DOL\DB\DOL.FDB"`: **с подключением она печатает строку версии СЕРВЕРА**,
без подключения — только версию утилиты (дефект, названный в `ADR-037`). Отказ `Column unknown` на
`MON$READ_ONLY` → снять перечень колонок `MON$TRANSACTIONS` из `RDB$RELATION_FIELDS` и повторить по
измеренному имени.

### Шаг 2 — какие колонки несут условия начисления (класс B, только чтение)

Снять состав `CONTRACTS` и `CONTRACTS_TERMS`: имена колонок, типы, длины и — если доступны —
описания на русском из метаданных. Это ответ на `Q-4` и вход всей формулы.

Запрос строится к `RDB$RELATION_FIELDS` в паре с `RDB$FIELDS`, с явными колонками, по двум именам
таблиц. Описания лежат в поле-BLOB: сначала `SET BLOB ALL;`, отказ на нём → `SET BLOBDISPLAY ALL;`,
отказ на обоих → **описания не добываются, и это записывается как факт**; имена и типы достаточны,
чтобы задача шла дальше. Наугад третью форму не подбирать.

**В артефакт идут все снятые колонки этих ДВУХ таблиц** — они наши used-таблицы, их состав разрешён
`ADR-009`. Инвентарь других таблиц не снимается и не пишется.

### Шаг 3 — портфель числами (класс B, только чтение): `Q-7` и `Q-8`

Одним скриптом, только агрегаты, без единого значения строки:
- число договоров по каждому состоянию (`CONTRACTS` в паре с `CONTRACT_STATES`, группировка по
  состоянию, печатаются название состояния и счётчик);
- число АКТИВНЫХ договоров — по тому состоянию (или состояниям), которое шаг 2 и справочник
  состояний называют действующим; какое именно — берётся из данных, а не из головы, и называется в
  артефакте явно;
- число активных договоров с ненулевым значением поля хранения;
- число активных договоров с ненулевым значением поля страховки.

**Ожидаемые величины назвать ДО прогона** (`ADR-023`): по хранению ожидается `6` — контрольный счёт
владельца; по портфелю ожидается либо `98`, либо `~82`, и обе цифры входные. **Совпало —
записывается как подтверждённое. Не совпало — расхождение называется поимённо, верен замер, а
конституция и реестр правятся не этой задачей, а решением.**

### Шаг 4 — значения параметров начисления по договорам (класс B, только чтение)

Снять значения полей условий (шаг 2) для двух групп:
- шесть активных договоров с ненулевым хранением — все, набор мал и сверяется целиком (`ADR-010 v3`);
- три активных договора БЕЗ хранения — контрольная группа: на них расширенная формула обязана дать
  ровно ту же величину, что и действующая.

**Санитария этого шага.** Идентификаторы договоров нужны Ilyas, чтобы найти их в приложении вендора,
и они остаются НА ЭКРАНЕ и в его записи вне репозитория. В артефакт идут порядковые номера
(«договор 1»…«договор 6», «контроль 1»…«контроль 3») и значения параметров начисления — ставки,
типы, даты, суммы тела. Имя клиента не запрашивается вовсе: в списке колонок запроса его нет.

### Шаг 5 — ОБЕ формулы выписаны, разница предъявлена ДО расчёта (класс A, стол)

Без обращения к базе. В артефакт пишутся:
- **Формула 1 — действующая** (`03 §4`): тело + начисленные проценты + пени на дату.
- **Формула 2 — расширенная**: то же плюс начисленное хранение, с явно названными типом начисления,
  базой начисления, периодом и минимальным сроком — из значений шага 4, а не из предположения.
  Страховка обрабатывается тем же механизмом (`ADR-010 v3`), на текущих данных ожидается ноль.
- **Разница между ними, ожидаемая величина:** на трёх контрольных договорах ровно `0`; на шести
  договорах с хранением — положительная величина, равная начисленному хранению на дату расчёта.
  **Это и есть критерий приёмки, выведенный из формулы, а не из свойства данных.**

Формулу начисления хранения не удаётся определить однозначно из значений → **не выбирать
правдоподобную**: назвать конкурирующие варианты, показать, какими числами они различаются на
шести договорах, и оставить выбор оракулу шага 7.

### Шаг 6 — наша величина на дату снимка (класс A, стол)

Посчитать балансовую цену по формуле 2 для шести договоров и по обеим формулам для трёх
контрольных. **Дата расчёта фиксируется и совпадает с датой снимка экрана шага 7** (`ADR-024`:
учётная система пересчитывает историю задним числом, недатированный эталон даёт ложные расхождения).
Расчёт «на сегодня» при снимке за вчера приёмкой не является.

### Шаг 7 — оракул: экран приложения вендора (класс B, человек за экраном)

Ilyas открывает приложение PawnShop и по тем же шести договорам на ТУ ЖЕ дату читает балансовую
величину. Снимок экрана он делает и хранит у себя — **в репозитории снимку места нет, и это не
недоделка, а решение `ADR-039`**: приватного сателлита ещё не существует, его создаёт `T-0-10`,
тогда снимки туда и уедут.

В артефакт сверки идёт обезличенная таблица: дата снимка · договор `N` · наша величина · величина с
экрана · расхождение · вывод.

### Шаг 8 — вердикт и патчи

- **Сошлось на всех шести и на трёх контрольных** → формула 2 записывается в `03 §4`; используемые
  поля — в `02 §3`; четыре строки реестра помечаются на закрытие в session-блоке.
- **Не сошлось хотя бы на одном** → **формула в `03 §4` НЕ записывается.** Расхождение
  предъявляется по каждому договору числами, задача закрывается этим фактом, вопрос уходит
  архитектору решением. Подгонка нашего расчёта под цифру экрана запрещена прямо (`00 §3-БИС(b)`,
  `ADR-039`): расхождение агрегата с экраном есть факт о семантике учётной системы, и закрывается
  он правилом, а не «уточнённым коэффициентом».

## Критерии приёмки

- Признак режима транзакции только на чтение напечатан ПЕРЕД полезными запросами в каждом шаге,
  идущем на сервер, — положительным фактом, а не отсутствием ошибки.
- Файл запроса каждого серверного шага напечатан целиком ДО запуска, первые байты показаны и не
  равны `239 187 191`.
- Состав колонок обеих таблиц условий предъявлен логом: имена, типы; описания либо предъявлены,
  либо явно названы недоступными с текстом отказа.
- Числа портфеля предъявлены логом: по состояниям, активные, с хранением, со страховкой. Ожидаемые
  величины названы ДО прогона; совпадение или расхождение с числами `6` и `98`/`~82` названо явно.
- **Обе формулы выписаны, и разница между ними предъявлена ДО расчёта ожидаемой величиной**
  (`ADR-023`): `0` на контрольной группе, положительная величина на шести.
- Наша величина и величина с экрана посчитаны НА ОДНУ дату, и дата названа в артефакте.
- Сверка предъявлена по всем шести договорам целиком, не выборкой; расхождение по каждому — число,
  а не слово.
- Артефакты обезличены: ни одного номера договора, ни одного имени клиента, ни одного пароля.
- Ни один критерий не закрывается кодом возврата; пустая или непарсимая выдача при нулевом коде
  есть гэп наблюдения.

## Что вернуть человеку

- Два артефакта в `/reference`: замер параметров и обезличенная сверка с оракулом.
- Одну строку вердикта: сошлась наша формула с приложением вендора на всех шести договорах или нет,
  и если нет — на каких и на сколько.
- Патчи `02 §3` и `03 §4` — только при сошедшемся оракуле.
- Три числа отдельно: активных договоров в портфеле; из них с хранением; из них со страховкой.

## Вне scope этой задачи

- **Любая запись в базу вендора**, включая расширение прав `GRANT`. Понадобилась таблица вне девяти
  → стоп и вопрос архитектору.
- **Создание `connector/mapping.json`** — файл, его формат и эталон отпечатка принадлежат `T-0-10`
  (`ADR-016`, `ADR-039`).
- **Создание приватного сателлита и перенос туда снимков** — `T-0-10`.
- **Правка конституции по размеру портфеля.** Замер даёт число; правка `00 §5` — решение, а не
  следствие замера.
- **Детектор продлений** (`T-0-4`) и **валидация статусной модели** (`T-0-6`): смежные задачи,
  здесь не трогаются, хотя таблица `OPERATIONS` уже доступна.
- **Прод-код конвейера.** Задача добывает знание и фиксирует контракт; код пишется поверх закрытого
  гэпа отдельной задачей.
