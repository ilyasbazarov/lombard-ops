# 10 · GCP_INFRA_PLAYBOOK — Грабли и рецепты

**Статус:** LIVE. Пополняется двумя путями: (а) перенос проверенных разделов из плейбука dom-prorab-catalog по мере надобности (ADR-007); (б) новые грабли этого проекта — через session-блоки. Правило `05`: бриф впервые трогает тип ресурса с разделом здесь → раздел идёт в его context-to-load.

## Разделы-кандидаты на перенос из референса (переносить при первом касании, не заранее)
- Cloud Scheduler · Job Creation & Idempotency (паттерн доисполнения после обрыва).
- Деплой cf-* из чистой папки (грабли рекурсивного зипирования `--source=.`).
- BQ load со staging-таблицей + INSERT…SELECT для таблиц с NOT NULL/DEFAULT.
- Heredoc-доставка SQL/shell в Cloud Shell (`/tmp` не переживает реконнект).
- Эмодзи/variation selector в SQL-литералах.

## Регион ресурсов — `europe-west3` (ADR-046)

Регион задан решением владельца 2026-08-12 и меняется только переездом. Грабля названа заранее,
потому что она тихая: **`bq mk` без явного `--location` кладёт датасет в `US`**, и регион датасета
BigQuery после создания не меняется — только удалить и создать заново. То же правило действует для
бакетов и Cloud Run. Приёмка `T-0-7` поэтому требует не «создано», а сплошного списка, доказывающего,
что ресурсов вне `europe-west3` нет, с положительным контролем.

## Новые разделы этого проекта (заполняются по факту)

### Firebird 2.5 из Python — ⏳ (T-0-2/T-1-1)
Драйвер, особенности диалекта, чтение RDB$-метаданных для guard, кодировка подключения. Заполнить по итогам первого рабочего подключения.

### Сетевой канал GCP ↔ контур клиента: АГЕНТ НА СЕРВЕРЕ — ⏳ (T-0-8)
Выбор сделан решением владельца 2026-08-12 (`ADR-046`, вариант Б `01 §4`): служба с только исходящим
трафиком кладёт выгрузку в GCS. Сюда — фактический рецепт: сервисный аккаунт и его ключ, установка
службы на Windows Server, расписание, диагностика, признаки обрыва, поведение при недоступности GCS.
Первая грабля названа заранее и проверяется шагом 1 `T-0-8`: исходящий HTTPS к `storage.googleapis.com`
из сети клиента может быть закрыт прокси или фильтром, а на старой Windows Server может не хватать
доверенных корневых сертификатов.

### Cloud Run (service + job) — ⏳ (T-1-1, T-2-1)
Деплой, секреты в env через Secret Manager, расписание jobs, минимальные инстансы.

### Identity Platform — ⏳ (T-2-1)
Включение, email/password провайдер, custom claims для ролей, проверка токена в API, создание пользователей без self-signup.

### RDP / PowerShell на ERP-сервере — практика
- Вставка в PowerShell: правый клик. Копирование: выделить → Enter.
- Вывод возвращать целиком, включая echo команды (untrusted-правило `05`).
- Ничего не устанавливать и не менять на сервере вне явного брифа; сервер — прод клиента.
