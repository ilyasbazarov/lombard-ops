# Негативный прогон проверки формы ответа · 2026-08-18

**Что это.** Предъявление признака-останова `tools/hooks/answer_check.sh` НЕГАТИВНОЙ веткой:
по одному намеренно нарушающему ответу на каждый блокирующий признак, поданному ЧЕРЕЗ ХУК
`Stop` фикстурным транскриптом — то есть тем же путём, каким приходит настоящий ответ, а не
режимом `--text`. «Ответ прошёл, нарушений нет» не удостоверяет ничего: положительная ветка
наступает всегда.

**Чего этот прогон НЕ доказывает, названо прямо.** Транскрипт здесь фикстурный, а не оставленный
живой сессией: доказано, что хук читает транскрипт, находит нарушение, печатает строку-нарушителя,
возвращает ответ кодом 2 и пишет строку в замер. НЕ доказано, что роль, получив возврат, чинит
ответ с первого раза — это ветка полевого замера, она снимается `tools/answer_stats.sh` после
первых сессий и в приёмке названа отдельной строкой (`ADR-074` §7).

**Как воспроизвести:** `bash tools/hooks/selftest.sh` (батарея 2, обе локали) — тот же набор
признаков плюс ветка пропуска и ветка предупреждения.

## Две ловушки самого прогона — обе поймали бы зелёный вердикт на пустом месте

Прогон переписывался дважды, и оба раза первая версия печатала бы благополучный итог при
неработающем измерении. Записаны, потому что следующий такой прогон будет писать тот же человек.

1. **Фикстура готовилась через `python3 -` со стороны stdin.** Интерпретатор сам читает
   программу со stdin, поэтому текст кейса приходил пустым: проверка честно отвечала «текста нет,
   проверять нечего» кодом 0, и все десять кейсов выглядели как «признак не сработал». Текст кейса
   кладётся ФАЙЛОМ.
2. **Корень репозитория вычислялся внутри подоболочки после `cd` во временный каталог.**
   `git rev-parse` там падает, путь к проверке склеивался пустым, и обе последние ветки
   возвращали код 127 — отказ ОКРУЖЕНИЯ, поданный как результат проверки. Итоговый абзац при
   этом продолжал утверждать, что всё сошлось: ровно тот случай, против которого написано правило
   «неуспех инструмента — тоже не факт». Корень берётся один раз, до всяких `cd`.

## Формат транскрипта — ЗАМЕРЕН на настоящем файле, а не принят со слов документа-донора

Разбор транскрипта — единственное место контура, читающее объект, который мы не производим.
Взять его устройство из переносимого документа значило бы построить код на чужом утверждении.
Замер снят на транскрипте ЭТОЙ сессии, каталог `~/.claude/projects/<проект>/<uuid>.jsonl`
(файл машинно-локальный, в репозиторий не входит и здесь не приводится):

```
строк JSONL: 262
типы объектов: {'ai-title': 27, 'queue-operation': 4, 'user': 61, 'attachment': 13,
                'custom-title': 27, 'assistant': 104, 'last-prompt': 26}
объектов assistant с непустым текстом: 2
```

Из 104 объектов `assistant` текст несут два: остальные — обращения к инструментам. Правило
выемки «последний непустой текстовый блок объекта `type == assistant`» на этом файле даёт именно
последнее сообщение владельцу. Сквозной прогон `answer_extract.py` → `answer_check.sh` на нём:

```
код выхода extract: 0
ОТВЕТ ВОЗВРАЩЁН — нарушений 3 (tools/hooks/answer_check.sh):
  1. [ФОРМА-1] строка 1 шапки не «Сделано:», а «Механика зелёная: 90 кейсов, провалено 0. …»
  2. [ФОРМА-1] строка 2 шапки не «Нужно от владельца:», а «<пусто>»
  3. [ФОРМА-1] строка 3 шапки не «Рекомендация:», а «<пусто>»
код выхода check: 2
```

Возврат здесь законный и показателен: промежуточное сообщение той же сессии, написанное ДО
введения правила, шапки не несёт. Признак сработал на настоящем ответе настоящей сессии.
