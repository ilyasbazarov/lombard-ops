# ADJ · `Q-18` — точка отсчёта начисления: разбор архитектора перед решением `ADR-040`

**Дата:** 2026-08-12 · **Роль:** архитектор · **Коммит на входе:** `5eb973d`
Предмет: сверка `T-0-3b` не сошлась ни на одном из восьми договоров. Этот файл держит числа и
совпавшие строки, на которых стоит `ADR-040`; в сообщении владельцу их нет по `05 §I`.

## 1. Что проверено арифметикой (воспроизведение формулы исполнителя)

Вход — только измеренные значения из `reference/T-0-3b_accrual_params_measurement_2026-08-12.md`
§4 (договор 1): тело `DEPOSIT_SUM = 200000` коп. = $2000.00, `DEPOSIT_PERC = 2.49990` %/мес,
`STORAGE_VAL = 0.05000` %/мес, `MIN_PERC_DAYS = 10`, `STORAGE_MIN_DAYS = 10`,
`IS_NOT_CALC_FIRST_DAY = 0`. Срок жизни договора в базе — 421 день (из
`T-0-3b_oracle_reconciliation_2026-08-12.md`, вывод).

```
проценты в день = 2000 × 2.49990 / 30 / 100 = 1.66660
хранение в день = 2000 × 0.05000 / 30 / 100 = 0.03333
проценты за 421 день = 701.64
хранение  за 421 день =  14.03
тело + проценты + хранение = 2715.67
```

**Вывод 1 — формула воспроизведена.** Наша величина в артефакте сверки — `2715.69`; расхождение
с пересчётом — 2 цента, объясняется порядком округления по дням. Значит дальше мы обсуждаем ту же
формулу, что считал исполнитель, а не свою.

## 2. Что проверено арифметикой (гипотеза «сдвинутая точка отсчёта»)

Экран вендора по договору 1: `2002.67` при теле `2000.00`, то есть весь наблюдаемый разрыв —
**$2.67**, договор НЕ просрочен (`PLAN_CLOSE_DATE` в будущем, пени нет вовсе).

```
нижняя граница процентов по MIN_PERC_DAYS = 10 × 1.66660 = 16.67
```

**Вывод 2 — гипотеза «точка отсчёта сдвинута продлением» ОДНА расхождение не закрывает.**
`MIN_PERC_DAYS = 10` задаёт нижнюю границу компоненты процентов $16.67 при ЛЮБОЙ точке отсчёта,
включая сегодняшнюю. Наблюдаемый разрыв $2.67 в шесть раз меньше этой границы. Из этого следует,
что на экране договора 1 либо проценты не начисляются вовсе, либо `MIN_PERC_DAYS` применяется не
так, как в формуле 1, либо экран показывает не ту величину, которую мы считаем. Ни один из трёх
исходов не выбирается здесь — все три остаются кандидатами.

## 3. Различающая деталь (гипотеза, а не факт)

```
2.67 / 0.03333 = 80.1 дня хранения
80 × 0.03333 = 2.6667 → 2.67
```

Наблюдаемый разрыв численно равен **80 дням хранения по измеренной ставке**. Это совпадение —
гипотеза, и она **различающая** (правило наблюдения «проба обязана различать исходы», `ADR-033`):
если на дату снимка по договору 1 проценты не начислялись, а хранение шло ~80 дней от последнего
цикла, то замер обязан показать это тремя значениями сразу — датой последней операции по договору,
значением `IS_PAY_PERC_ON_FUTURE` и значением `START_MOMENT`. Не показал — гипотеза снята, а не
«уточнена коэффициентом».

## 4. Поля, лежащие под ответом, но не снятые ЗНАЧЕНИЯМИ

Состав колонок снят (§1 артефакта замера), значения — нет. Все перечисленные поля живут в
used-таблицах `CONTRACTS` / `CONTRACTS_TERMS`, права на них уже выданы (`briefs/T-0-5.md`, список
из девяти таблиц), то есть повторный замер новых грантов не требует:

| Поле | Таблица | Почему относится к делу |
|---|---|---|
| `IS_PAY_PERC_ON_FUTURE` | `CONTRACTS_TERMS` | «оплата процентов наперёд» — если взведено, накопленных процентов на экране может не быть вовсе |
| `START_MOMENT` | `CONTRACTS_TERMS` | «начало действия тарифа» — прямой кандидат в точку отсчёта |
| `ID_OP` | `CONTRACTS_TERMS` | «связь с операцией смены тарифа» — выводит на дату последнего цикла через `OPERATIONS` |
| `ACC_PAY_SCHEME` | `CONTRACTS_TERMS` | «порядок погашения начислений» — определяет, что гасится первым при продлении |
| `ID_PREV_CONTRACT` | `CONTRACTS` | «связь с предыдущим договором (переоткрытие)» — механизм «Переоткрытие» в чистом виде |
| `EXCEED_DAYS` / `EXCEED_MONTHS` / `IS_PRIVILEGE_IN_EXCEED_DAYS` | `CONTRACTS_TERMS` | льготные дни просрочки — влияют на дни начисления до всякой пени |

## 5. Что `ID_PREV_CONTRACT` уже сужает в `T-0-4`

Метаданные описывают его дословно как «связь с предыдущим договором (переоткрытие)». Значит
механизм «Переоткрытие» заводит НОВУЮ строку договора, и у переоткрытого договора `CONTRACT_DATE`
свежая, а не первоначальная. Договор 1 живёт 421 день одной строкой — следовательно его цикл либо
продлевался механизмом «Погашение» (та же строка), либо не продлевался вовсе. Формулировка
«`CONTRACT_DATE` хранит дату ПЕРВОЙ выдачи» верна самое большее для одной из двух ветвей `T-0-4`
и в общем виде репозиторием не подтверждена: `§1` артефакта замера описывает поле как «дата
заключения договора», не более.
