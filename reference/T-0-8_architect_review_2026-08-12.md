## 1. ГЛАВНОЕ: вердикт шага 1 замером НЕ доказан

`reference/T-0-8_agent_channel_measurement_2026-08-12.md` печатает вердикт «не пройдено» на
основании строки «Совпадает с запрошенным хостом: False» для `oauth2.googleapis.com`. Проверяю,
что именно эта строка измеряет.

### 1.1 Проба мерила CN, а предмет приёмки — пригодность эндпоинта

Артефакт во всех пяти прогонах печатает ровно одно поле сертификата — `Subject` (`CN=...`).
**Поле `subjectAltName` (SAN) не напечатано ни разу, ни для одного хоста.**

Соответствие сертификата запрошенному имени определяется списком `dNSName` в расширении SAN;
`CN` используется только как запасное поле при ОТСУТСТВИИ SAN. Значит утверждение «identity сервера
не совпадает с запрошенным доменом» из напечатанного лога **не следует**: измерено было равенство
строки `CN` строке хоста, а это другой предикат.

Это ровно тот дефект, который в проекте уже назван дважды: `ADR-037` — «критерий приёмки и команда,
которой он закрывается, обязаны совпадать по предмету»; `ADR-033` — «проба обязана различать
исходы». Прогон 1 в том же артефакте уже был снят по этой причине, прогоны 2–5 починили ОДИН
дефект пробы (разведение HTTP-ответа и транспортного отказа) и унаследовали второй.

### 1.2 Тот же лог содержит признак ИСПРАВНОГО канала

Прогон 2 (`HttpWebRequest`) записывает: `oauth2.googleapis.com` — **HTTP-код 404**, то есть ответ
пришёл, запрос прошёл целиком. У `HttpWebRequest` проверка имени сертификата стоит по умолчанию:
при реальном несовпадении имени соединение падает на handshake с ошибкой доверия и HTTP-кода
не существует вовсе. Код `404` на `GET /` — штатный ответ токенного эндпоинта, у которого рабочий
путь `POST /token`.

Оговорка, названная явно: скрипт пробы **не сохранён** — ни в `scripts/`, ни внутри артефакта. Если
в нём стоял разрешающий `ServerCertificateValidationCallback`, довод 1.2 теряет силу. Довод 1.1
силы не теряет ни в каком случае. Отдельный факт метода: вердикт, чей скрипт не предъявлен,
невоспроизводим — артефакт печатает вывод, но не команду.

### 1.3 Асимметрия двух хостов объясняется без гипотезы о перехвате

Артефакт сам фиксирует: цепочка `oauth2.googleapis.com` **подлинная** (`Google Trust Services`,
`ChainStatus` пуст, валидна без замечаний), IP из адресного пространства Google. Подлинный
сертификат Google на IP Google — это Google, а не точка перехвата. Разница с
`storage.googleapis.com` (там `CN` совпал) объясняется тем, каким сертификатом фронтенд обслуживает
каждое имя, и никакой гипотезы о сети клиента не требует.

### 1.4 Статус находки

Это **гипотеза, а не факт** — ровно та граница, из-за отсутствия которой сгорел `ADR-006`.
Различающая проба стоит одного захода на RDP и написана ниже, п. 5. Пока она не сделана, верны
оба утверждения: «канал не пригоден» не доказано и «канал пригоден» не доказано. **Разворот
архитектуры на недоказанном вердикте есть та же ошибка, что и продолжение работы на нём.**

Цена ошибки несимметрична и потому решает: перемер — один шаг класса B без установки чего-либо;
разворот — переписывание `01 §1`/`§4`, перевыпуск брифа, новый постоянный облачный ресурс с
администрированием, реконнект-логика WG на динамический IP, 1–2 сессии при 19 днях до 31 августа.

## 3. Третий путь, которого нет в выжимке: агент БЕЗ `oauth2.googleapis.com`

Если перемер подтвердит, что токенный эндпоинт с этой сети действительно непригоден, разворот на
туннель всё равно не единственный выход, и он не первый по цене.

Замером **установлено положительно**: `storage.googleapis.com` с сервера клиента доступен и отдаёт
корректный сертификат — воспроизведено во всех прогонах, включая контрольный через 10 минут. Не
работает (предположительно) ровно один эндпоинт — обмен ключа сервисного аккаунта на токен.

Подписанный URL для загрузки в GCS формируется **локально**, приватным ключом сервисного аккаунта,
без единого сетевого обращения; загрузка идёт обычным `PUT` на `storage.googleapis.com`. То есть
агент может выкладывать выгрузку в бакет, ни разу не обратившись к `oauth2.googleapis.com`.

Что это меняет: канал остаётся исходящим, входящих соединений к контуру клиента по-прежнему нет,
красные линии `00 §4` не двигаются, новый облачный ресурс не заводится, `01 §4` правится одной
строкой вместо переписывания. Цена: подписанные URL живут ограниченное время, поэтому агент
подписывает свой URL сам перед каждой загрузкой — ключ SA у него и так есть по шагу 5 брифа.

Это тоже **гипотеза о конструкции, а не готовое решение**: её проверка — отдельный шаг, и он
дешевле туннеля. Порядок разбора от этого меняется: сначала перемер, потом подписанный URL, и
только потом туннель.

## 5. Решающая проба — готова к запуску, класс B, ничего не меняет

**Карточка подтверждения.**
*Что исполняется:* два исходящих HTTPS-запроса к `oauth2.googleapis.com` — чтение списка имён
сертификата и один `POST` с заведомо недействительным телом. Ничего не устанавливается, не
записывается, секретов не участвует.
*На каком объекте:* сервер ERP `192.168.88.209` по RDP, PowerShell.
*Чем откатывается:* откат предмета не имеет — только сетевые запросы на чтение.

Скрипт целиком, без плейсхолдеров. Сохранить как `C:\Temp\probe_oauth.ps1` и запустить
`powershell -ExecutionPolicy Bypass -File C:\Temp\probe_oauth.ps1`; вывод передать дословно.

```powershell
$ErrorActionPreference = 'Continue'
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
$h = 'oauth2.googleapis.com'

'===== ПРОБА A: список имён (SAN) в сертификате ' + $h + ' ====='
try {
    $tcp = New-Object Net.Sockets.TcpClient($h, 443)
    $cb  = [Net.Security.RemoteCertificateValidationCallback] { param($a,$b,$c,$d) $true }
    $ssl = New-Object Net.Security.SslStream($tcp.GetStream(), $false, $cb)
    $ssl.AuthenticateAsClient($h)
    $cert = New-Object Security.Cryptography.X509Certificates.X509Certificate2($ssl.RemoteCertificate)
    'SUBJECT : ' + $cert.Subject
    'ISSUER  : ' + $cert.Issuer
    $ext = $cert.Extensions | Where-Object { $_.Oid.Value -eq '2.5.29.17' }
    if ($null -eq $ext) {
        'SAN     : РАСШИРЕНИЕ ОТСУТСТВУЕТ'
    } else {
        $san = $ext.Format($false)
        'SAN RAW : ' + $san
        'СОДЕРЖИТ oauth2.googleapis.com : ' + [bool]($san -match 'oauth2\.googleapis\.com')
        'СОДЕРЖИТ *.googleapis.com      : ' + [bool]($san -match '\*\.googleapis\.com')
    }
    $ssl.Close(); $tcp.Close()
} catch {
    'ПРОБА A УПАЛА: ' + $_.Exception.Message
}

''
'===== ПРОБА B: POST на /token со ШТАТНОЙ проверкой сертификата ====='
try {
    $body = [Text.Encoding]::ASCII.GetBytes('grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer&assertion=nonsense')
    $req = [Net.HttpWebRequest]::Create('https://oauth2.googleapis.com/token')
    $req.Method        = 'POST'
    $req.ContentType   = 'application/x-www-form-urlencoded'
    $req.ContentLength = $body.Length
    $st = $req.GetRequestStream(); $st.Write($body, 0, $body.Length); $st.Close()
    $resp = $req.GetResponse()
    'HTTP    : ' + [int]$resp.StatusCode
    (New-Object IO.StreamReader($resp.GetResponseStream())).ReadToEnd()
} catch [Net.WebException] {
    if ($null -eq $_.Exception.Response) {
        'ТРАНСПОРТНЫЙ ОТКАЗ (HTTP-ответа нет): ' + $_.Exception.Message
        'STATUS  : ' + $_.Exception.Status
    } else {
        'HTTP    : ' + [int]$_.Exception.Response.StatusCode
        (New-Object IO.StreamReader($_.Exception.Response.GetResponseStream())).ReadToEnd()
    }
}
```

**Исходы различаются наблюдаемо — в этом смысл пробы.**

| Что напечатано | Что это значит | Что дальше |
|---|---|---|
| Проба A: `СОДЕРЖИТ oauth2.googleapis.com : True` **и** проба B: `HTTP : 400` с телом JSON | Эндпоинт подлинный и функционально доступен. Вердикт шага 1 — ложноотрицательный | `T-0-8` продолжается с шага 2 без единой правки архитектуры; разворот отменяется решением |
| Проба A: обе строки `False` (или SAN отсутствует) **и** проба B: `ТРАНСПОРТНЫЙ ОТКАЗ` | Вердикт шага 1 подтверждён нужным предикатом | Идём в п. 3 (подписанный URL), туннель — третьим |
| Пробы расходятся между собой | Ни один вывод не берётся; печатается расхождение, назначается третья проба | Стоп, `CONTEXT GAP`, гадать запрещено |

Проба B несёт собственный положительный контроль: `HTTP 400` с телом Google означает, что штатная
проверка сертификата .NET сертификат **приняла**, — то есть отвечает ровно на вопрос п. 1.2.

## 8. Что остаётся владельцу

Ровно одно решение: **перемерить шаг 1 нужным предикатом до разворота — или развернуться сразу.**
Оба варианта законны; они различаются ценой ошибки, а не правотой.

Решение фиксируется `ADR-048` в следующей сессии, после результата пробы (или сразу после ответа
«разворачиваемся без перемера» — тогда ADR пишется по пути 3 и в него входит требование
предъявить живой peer, п. 2).
