## 1. Доставка кода на сервер

Код агента (ZIP, 9 файлов — планировавшиеся 8 файлов `connector/agent/` плюс `run_daily.py`,
написанный сессией `2026-08-13`) доставлен через RDP-буфер обмена в виде base64-текста, как и
планировалось разделом 4 проектного артефакта («вставка через `notepad`/`certutil -decode`
base64-текстового представления»).

**Отклонение от гладкого сценария:** первая попытка вставить весь текст одним куском (43825
символов) дала повреждённый ZIP — при декодировании и распаковке обнаружилось расхождение.
Рабочая гипотеза (НЕ подтверждена измерением, зафиксирована как гипотеза, не факт): потеря одного
символа в буфере обмена RDP при большом объёме вставки. Причина не измерялась отдельно — обходной
путь найден и предъявлен, поиск причины оборванной вставки не входит в предмет этого шага.

**Исправление:** текст разбит на 2 части (~22 KB каждая), после вставки каждой части на сервере
сверялась контрольная сумма SHA-256 с локально посчитанной. Итоговые суммы совпали на обеих частях.
`certutil -decode` дал корректный ZIP (32866 байт) — контрольная сумма самого ZIP-файла (не только
частей текста) не сверялась отдельно этим шагом, положительным фактом служит успешная распаковка
`Expand-Archive` без ошибки и присутствие всех 9 ожидаемых файлов после неё (предъявлено листингом
каталога `C:\LombardAgent\code\connector\agent\` владельцем).

## 3. Отказ S4U-регистрации задачи и диагностика (пункт 5 скрипта)

**Факт отказа:** `Register-ScheduledTask` с `New-ScheduledTaskPrincipal -LogonType S4U` под
учёткой `lombard-agent-svc` отбит с `Access Denied` (`HRESULT 0x80070005`).

**Полный перечень проверенных гипотез причины — все дали ОТРИЦАТЕЛЬНЫЙ результат** (ценность для
будущих сессий на этом сервере — записать как факт-загадку, не как решённую причину):

1. Полная административная элевация сессии подтверждена — `[Security.Principal.WindowsPrincipal]::...IsInRole(Administrator)` → `True`. Отказ не объясняется отсутствием элевации.
2. Альтернативный API даёт тот же отказ — `schtasks /create /xml` с явным S4U в XML тоже `Access Denied`. Отказ не специфичен для командлета `Register-ScheduledTask`.
3. Права на каталог `C:\Windows\System32\Tasks` в норме — `Администраторы:(F)`, `SYSTEM:(F)`. Не объясняется правами каталога.
4. Создание задачи планировщика под СОБСТВЕННОЙ учёткой администратора (без S4U, без смены принципала) — `УСПЕХ`. Общая работоспособность Task Scheduler и прав каталога подтверждена; отказ специфичен именно для S4U-регистрации под ЧУЖИМ принципалом.
5. Антивирус/EDR на сервере не найден: `SecurityCenter2` пуст, PowerShell-модуль Defender отсутствует вовсе, ни одного процесса/службы по известным именам AV не обнаружено. Не объясняется вмешательством AV/EDR.
6. Security-лог Windows не содержит audit failure событий (4656/4660/4673/4674) за время попытки. Не объясняется зафиксированным отказом аудита.
7. Явных `SeDenyBatchLogonRight`/`SeDenyServiceLogonRight` нет. Единственный `SeDeny*`-запрет у учётки — `SeDenyInteractiveLogonRight`, поставленный намеренно при заведении `lombard-agent-svc` (`11_INFRA_FACTS`), к батч-логону отношения не имеет.
8. `lombard-agent-svc` активна, не заблокирована, состоит в builtin `Users` — проверено по SID `S-1-5-32-545`. **Уточнение к предыдущему наблюдению:** `net user` в локализованном выводе показал пустое членство в группах — это артефакт отображения команды, не факт отсутствия членства (проверено прямой проверкой по SID).
9. У администратора отсутствовал `SeAssignPrimaryTokenPrivilege` (частая известная причина именно такого отказа при регистрации задач с альтернативным логоном) — выдан через `secedit` (`*S-1-5-32-544` добавлен группе администраторов). Проверено, что применение требует полного выхода/входа, не просто нового окна PowerShell — токен не обновляется без релогина. После полного выхода/входа право **подтверждено в локальной политике** (`secedit /export` печатает строку), но **НЕ появилось в `whoami /priv`** даже после релогина. **Причина этого расхождения НЕ установлена.**
10. **Решающий тест:** заведена одноразовая тестовая локальная учётка `t0_8_test_s4u` (НЕ `lombard-agent-svc`), ей выдан `SeBatchLogonRight`, предпринята попытка S4U-регистрации задачи под НЕЙ — **тот же отказ `Access Denied`.** Это доказывает: проблема системная для S4U-регистрации под ЛЮБОЙ учёткой, отличной от вызывающей, на этом конкретном сервере — не специфична для `lombard-agent-svc`. Тестовая учётка и тестовая задача удалены сразу после теста.

**Корень проблемы НЕ установлен.** Не GPO deny (гипотеза 7 отрицательна), не ACL каталога задач
(гипотеза 3 отрицательна), не AV/EDR (гипотеза 5 отрицательна), не привилегия вызывающего
администратора в исходном виде (гипотеза 9 частично устранена выдачей права, но расхождение
`secedit`/`whoami` осталось необъяснённым). Зафиксировано как факт-загадка для будущих сессий на
этом сервере, причина не выдумывается постфактум.

## 4. Решение по факту — переход на классическую регистрацию с паролем

**Отказ от S4U.** Переход на `schtasks /create ... /ru "WIN-RSAGM3JEOUA\lombard-agent-svc" /rp <пароль>`
для ТОЙ ЖЕ учётки `lombard-agent-svc` (не администратора; остальные ограничения учётки —
`SeDenyInteractiveLogonRight`, членство — не изменены).

**Обращение с паролем:** пароль учётки сброшен на новый случайный (28 символов) НЕПОСРЕДСТВЕННО
перед регистрацией задачи, использован ровно один раз в команде регистрации и сразу после этого
переменная-держатель в сессии PowerShell обнулена штатным присваиванием пустого значения. Пароль
нигде не печатался, не логировался, не сохранён нами ни в каком виде. Windows Task Scheduler хранит
собственную зашифрованную копию внутри LSA — это штатный документированный механизм платформы для
password-based батч-логона задач, не решение, изобретённое этой сессией.

**Результат: УСПЕХ.** `schtasks /query /tn LombardAgentDailyRun /v /fo list` подтвердил:
`Enabled`, ежедневный триггер `03:00`, `Запуск от имени: lombard-agent-svc`, `Режим входа в
систему: Интерактивный/фоновый` — это стандартное отображение `schtasks` для password-based батч-
логона, не признак ошибки конфигурации.
