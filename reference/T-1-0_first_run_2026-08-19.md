## 3. Причина установлена целиком: два разных уровня прав BigQuery перепутаны

```
$ bq show --format=prettyjson project-c451b48a-07ae-4de4-961:lombard_ops
{'role': 'WRITER', 'userByEmail': 'lombard-pipeline@project-c451b48a-07ae-4de4-961.iam.gserviceaccount.com'}
… (плюс проектные projectWriters/projectOwners/projectReaders)

$ gcloud projects get-iam-policy project-c451b48a-07ae-4de4-961 --flatten="bindings[].members" \
    --format="value(bindings.role)" --filter="bindings.members:lombard-pipeline@…"
roles/secretmanager.secretAccessor
```

`lombard-pipeline` несёт `WRITER` на датасете `lombard_ops` (dataset ACL, выдано `T-0-7`,
`11_INFRA_FACTS.md`) — это право писать данные В датасет, измерено верно и подтверждено сейчас
второй раз. Но `bigquery.jobs.create` — ОТДЕЛЬНОЕ, ПРОЕКТНОЕ разрешение (создать job вообще,
включая load-job), которое роль WRITER на датасете не несёт. Ни project-level IAM `lombard-pipeline`
(только `secretAccessor`), ни dataset ACL его не дают. **Разрыв существовал с 2026-08-12 (`T-0-7`),
не был замечен ни одной из предыдущих сессий — потому что до сегодня ни один прогон конвейера
не доходил до реального вызова BQ load.**

## 6. `T-1-0` НЕ закрыта — ручной вызов приёмку не засчитывает

Бриф запрещает это дословно (`briefs/T-1-0.md`, шаг 8): «не форсировать `gcloud scheduler jobs
run` — это ручной запуск и противоречит формулировке приёмки "ни один прогон не запускался
руками"». Тот же запрет распространяется на прямой вызов функции — источник запуска обязан
быть `cloudscheduler.googleapis.com`, не человек. Ручной вызов этого раздела снял риск
(доказал, что фикс `roles/bigquery.jobUser` работает) и остаётся в артефакте диагностикой, но
**не является ни «Прогоном 1», ни «Прогоном 2»** приёмки.

Автоматический прогон дня `2026-08-19` (`lastAttemptTime: 02:00:00Z`, §1–3 выше) — упал, факты
приёмки (строка `loans_raw`, статус, `message_id`) не произведены, значит и он не засчитывается
как «Прогон 1».

**Остаётся исполнить:** «Прогон 1» — первый УСПЕШНЫЙ автоматический прогон, кандидат
`2026-08-20T02:00:00Z` (уже назначен `scheduleTime`); «Прогон 2» — на следующие сутки,
`2026-08-21T02:00:00Z`. Оба — наблюдение, класс A, без вмешательства. Точка переключения
режима (`ADR-052`) остаётся непройденной до тех пор.
