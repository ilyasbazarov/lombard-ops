# T-0-6 · Валидация статусной модели на данных · 2026-08-19

**Объект замера определён:** боевая база PawnShop (Firebird) на сервере ERP (`11_INFRA_FACTS.md`,
строки «Сервер», «СУБД»), таблицы `CONTRACTS`, `CONTRACT_STATES`, `CUSTOM_FIELDS_VALUES`,
`DIR_CUSTOM_FIELDS` и др. из девяти разрешённых (`briefs/T-0-5.md`, «Список таблиц»). Механизм чтения
(`connector/agent/discovery_t0_6.py`, `scripts/T-0-6_run_discovery.ps1`) написан этой сессией — не
подменяет объект замера, читает уже существовавшие данные.

**Кем исполнено:** исполнитель (Claude, без прямого доступа к серверу) готовил код, SQL, инструкции и
карточки подтверждения — класс A. Все действия класса B (доставка кода на сервер, чтение боевой базы)
исполнены владельцем (Ilyas) лично по RDP на сервере ERP, каждое по отдельно подтверждённой карточке.
Результаты предъявлены исполнителю текстом координатора построчно.

**Закрывает пока:** шаги 1–4 брифа `briefs/T-0-6.md`. Шаги 5–9 — по мере подтверждения карточек.

`LombardAgentDiscoveryT0-4a`, заявленная решением (`06_DECISIONS_LOG.md`,
`reference/T-1-1_gap_review_2026-08-19.md`) как переиспользуемая для T-0-6 «без
отдельной поездки», реально всё ещё вызывала `T-0-4a_run_discovery.ps1` —
`/tr` не был перенаправлен. Первый запуск (`t0_4a_discovery_20260819_155741.*.log`)
прошёл вхолостую по старым запросам T-0-4a — только разрешённые таблицы,
`MON$READ_ONLY=1` на каждый вызов, `EXITCODE: 0`, без единой операции записи,
боевая база не пострадала. Пароль `lombard-agent-svc` не был известен никому
(заведён случайным один раз при `T-0-8`, не логировался) — потребовался сброс
пароля (`net user lombard-agent-svc *`, класс B, значение не покидало терминал
владельца) перед `schtasks /change /tn "LombardAgentDiscoveryT0-4a" /tr "...
T-0-6_run_discovery.ps1" /rp *`. После перенаправления — подтверждено
`schtasks /query`.
