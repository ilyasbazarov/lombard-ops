## Шаг 6 — срок договора по активным, в разрезе продлений (класс B)

**Инцидент запроса (инфраструктура, не данные):** первая версия `active_term_histogram`
упала `SQLCODE -104` — Firebird 2.5 отбил повтор коррелированного `EXISTS`
внутри `CASE` прямо в `GROUP BY`. Правка — вычисление через `WITH`-CTE
(коммит `cc22ebe`), файл передоставлен на сервер повторно, SHA-256
`4fbb64e7677bea7f4d8730b880043d80ba0fc84b0d26e1573532468066472399` совпал.

```
active_term_histogram (TERM_DAYS, IS_RENEWAL, CNT):
  (29,  0, 45)
  (29,  1, 44)
  (225, 1,  1)
  (242, 1,  1)
  (263, 1,  1)
  (323, 1,  1)
  (450, 1,  1)
  (сумма = 94)
```

**Вердикт по короткому сроку (передаётся архитектору, не правится здесь):**
материальной группы КОРОТКИХ сроков (аналогичной 9-дневной, 7.5% истории,
`03 §2` строка 108) среди активных **нет** — ни одной записи с `TERM_DAYS=9`.
Доминирующий срок — 29 дней (98.9% активных, 89/94: 45 без продления + 44 с
продлением) — это СТАНДАРТНЫЙ срок займа (72.9% всей истории, та же строка
`03 §2`), не короткий. Вопрос закрывается как снятый, порог `03 §1` правки не
требует.

**Расхождение счёта, названо поимённо (`★ Наблюдение`):** сумма гистограммы
94 против 95 активных (`active_status_distribution`, шаг 5). `anomaly_empty_plan_close_date=0`
исключает пустую `PLAN_CLOSE_DATE`; следовательно ровно один активный договор
имеет пустую `CONTRACT_DATE` — класс аномалии, не учтённый ни шагом 1 брифа,
ни `ADR-070`. Замер этой сессии его не считает отдельным запросом (вне
списка шага 1) — называется архитектору как новый гэп, не подставляется.

## Шаг 7 — `renewal_share_active` и гипотеза 44% (класс B)

```
renewal_share_active: RENEWED_ACTIVE=49, ACTIVE_TOTAL=94 → 49/94 = 52.1%
op_vid0_distinct_contracts: DISTINCT_WITH_OP_VID0=536, TOTAL_CONTRACTS=2520
```

**Расхождение с шагом 5, названо (`★ Наблюдение`):** `ACTIVE_TOTAL` этого
запроса — 94, не 95 (шаг 5, 16 минут раньше на боевой, живой базе). Реальное
изменение состояния между прогонами на проде, не ошибка замера — оба числа
предъявлены дословно на свою минуту.

**Различающая проверка гипотезы 44% (`ADR-023`):** счёт РАЗЛИЧНЫХ договоров с
`OP_VID=0` — 536 из 2520 (21.3%), заметно меньше ожидаемых ~1111 (T-0-4a мерил
операции, не различные договоры — 536 отсюда следует, что на договор в
среднем ~2.07 операции `OP_VID=0`). **Вердикт: гипотеза о происхождении 44%
через `OP_VID=0` ОТВЕРГНУТА** различающей проверкой — счёт распадается вдвое
при переходе от счёта операций к счёту различных договоров.
